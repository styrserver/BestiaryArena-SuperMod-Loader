# Creature combat snapshot: manual update

The Cyclopedia "Combat details" panel (title-bar toggle beside the creature name) shows each
creature's ability constants: cooldowns, durations, damage bases, AP ratios, caps. The game does not
expose them through its API, only inside its minified creature bundle, so the mod ships a snapshot:

- `CREATURE_COMBAT_DATA` in `database/creature-database.js`, between the
  `// BEGIN CREATURE_COMBAT_DATA` and `// END CREATURE_COMBAT_DATA` markers.
- Never edit that block by hand. It is generated by `tools/check-creature-combat.mjs`.

Nothing refreshes it automatically. After a game update the snapshot stays at the old numbers until
you run the steps below. Background on what the constants mean: `docs/game_state_api.md`,
"Per-creature ability constants".

## When to run it

- After the game ships an update (patch notes, new creatures, rebalanced abilities).
- When a Cyclopedia combat panel looks wrong (for example constants that do not match the in-game
  ability tooltip).

## Steps

Run from the project folder (the one that contains `tools/` and `database/`). Needs Node 18+ (global
`fetch`) and an internet connection; it downloads the live game chunks from bestiaryarena.com.

1. Check for drift (read-only, changes nothing):

   ```bash
   node tools/check-creature-combat.mjs
   ```

2. Read the result:

   | Output / exit code | Meaning |
   |---|---|
   | `OK: N creatures match the snapshot.` (exit 0) | Snapshot is current. Stop here. |
   | `NEW <id> <name>` (exit 1) | Creature in the game with no snapshot entry. |
   | `CHANGED <id> <name>: KEY: old -> new` (exit 1) | A constant, or `attackDelayMs`, differs. |
   | `REMOVED <id> <name>` (exit 1) | Snapshot entry for a creature the game no longer has. |
   | error message (exit 2) | Download or parsing failed. The result is not "OK": do not trust the snapshot as current. |

3. Review the lines. Check that each change is plausible: a rebalance shows as a few `CHANGED`
   constants; a whole creature gaining or losing its constants usually means the extractor picked the
   wrong definition (see "Troubleshooting").

4. Write the new snapshot:

   ```bash
   node tools/check-creature-combat.mjs --update
   ```

5. Re-run the check. It must now print `OK`:

   ```bash
   node tools/check-creature-combat.mjs
   ```

6. Open the Cyclopedia in the game, toggle the combat panel on a creature you changed, and compare
   with the game's own ability tooltip. Commit `database/creature-database.js`.

## Troubleshooting

- **Exit 2, `creature bundle not found` / `only N creature entries found`.** The game's bundle
  layout changed, so the extractor's anchors no longer match. Fix `tools/check-creature-combat.mjs`;
  do not run `--update` until the check parses normally.
- **A creature shows constants that belong to something else.** Two metadata objects can share a name.
  Example: the "Old Minotaur Archer" boss (lifesteal below 25% HP) reuses the name "Minotaur Archer"
  but the playable one (id 34) stocks bolts. The extractor resolves this with the game's registry
  entry `34:{constructor:..,metadata:..}`; if a creature is still wrong, look for a second definition
  of that name in the chunk and check which one the registry points to.
- **Creatures missing from the snapshot.** Chubby / Spiky / Psychic / Sturdy / Mystic Gazer and
  Football Elemental are known gaps: their metadata is not in either shape the tool reads.
- **Attack delay.** `ad` is the base auto-attack delay in ms. `null` means the 2000 ms engine
  default.

## Constant overrides (experimental, Map Editor)

The Map Editor creature panel lists every snapshot constant under "Native combat constants" as an
editable number (times in ticks). Like Attack CD, the numbers are saved on the placed creature
(`actor.combatConstants`, snapshot units) and apply only while the Map Editor test battle runs; leaving
the test restores the originals.

- `content/ba-combat-chunk.js`: shared parser. `tools/check-creature-combat.mjs` uses the same code, so
  a drift check that passes means the instrumenter still finds the same constant objects.
- `content/ba-combat-overrides.js`: MAIN-world script (`world: "MAIN"`, `document_start` in
  `manifest.json`). Wraps `webpackChunk_N_E.push` and instruments the creature module so each constant
  object registers itself (`self.__baCT`); no value is changed at load. API:
  `window.BestiaryCombatOverrides.applyLive(overrides)` / `restoreLive()` / `isReady()`.
- Same-type creatures on a map share one constant table, so differing values on them: last one wins.
  Event variants that share a constant object behave the same way.
- Values the game copies elsewhere at module load (not read from the table at use time) are not affected.
- Chrome build only. `manifest_firefox.json` (MV2) has no MAIN-world content scripts, so the panel
  says so and the values are saved but not applied.
- If a game update changes the module layout, the hook leaves the original module untouched and logs an
  Error Log entry; run the check tool, fix `ba-combat-chunk.js`, then `--update`.
